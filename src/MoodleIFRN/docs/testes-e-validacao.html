REGRESSÃO · CONTRATOS · DIAGNÓSTICO

Testes, linha de base e fixtures

Os testes IFRN são majoritariamente scripts Node independentes em src/MoodleIFRN/tests/; o Jest/Gulp do núcleo é um grupo separado. Preserve casos de sessão mesmo quando falhem: uma falha pode ser a evidência do defeito que o teste protege.

P0.4 permanece protegido: não apague, ignore, enfraqueça ou altere as expectativas de concorrência de sessão para fazer a suíte passar. O patch e os contratos precisam continuar íntegros.

01 · COMANDOS

Executar testes

Os scripts do pacote raiz estão declarados em package.json. test:ci executa Gulp e Jest em modo serial; é distinto da suíte Node MoodleIFRN.

Jest e tarefas GulpShell POSIX; Windows use Git Bash/WSL se a atribuição NODE_ENV falhar
npm run test:ci

Não inclui automaticamente todos os scripts Node em src/MoodleIFRN/tests/. No Windows, o script contém sintaxe Unix para definir NODE_ENV; use um shell POSIX ou registre a falha de compatibilidade sem editar o script por conveniência.

Regressão pontual de navegaçãoNode 22
node --test src/MoodleIFRN/tests/course-navigation-failure.test.cjs
Suíte Node no PowerShell (exclui teste JVM com efeitos colaterais)Raiz do repositório
$testFiles = Get-ChildItem 'src/MoodleIFRN/tests' -File -Recurse | Where-Object {
  $_.Name -match '\.test\.(cjs|mjs)$' -and $_.Name -ne 'native-persistence-contract.test.cjs'
} | ForEach-Object { $_.FullName }
node --test --test-concurrency=2 @testFiles

Este padrão consta no manual e evita o teste que compila Java e grava evidências. Reveja a lista de arquivos antes de reutilizar, pois o conjunto muda ao longo do desenvolvimento.

Os documentos da release registram resultados distintos: 358 testes em 50 arquivos na verificação do checkout de release e 369 em 51 na auditoria de limpeza. Os comandos/escopos e snapshots diferem; não compare as contagens como se fossem a mesma linha de base. Nenhum teste foi executado nesta tarefa documental.

04 · REGRAS DE LINHA DE BASE

Como interpretar os resultados

  • Antes da mudança, registre comando, contagem, falhas, código de saída e testes não executados. Diferencie falhas preexistentes de regressões.

  • Preserve autenticação, isolamento de conta, origem postMessage, recuperação e P0.4.
  • Testes unitários não provam login SUAP, OAuth, persistência nativa ou curso funcionando em aparelho. Siga o roteiro Android físico.
