04 · DESENVOLVIMENTO

Build web e customizações IFRN

O painel leve em src/MoodleIFRN/mobilemoodle/ tem build própria. A build nativa Angular/Cordova é outra etapa. Não confunda a geração de mobilemoodle.js com uma APK.

Compilar o painel mobilemoodle (TypeScript + SCSS)Raiz do projeto
npm run build:mobilemoodle

Gera/atualiza bundle e CSS do painel e sincroniza Ionic/Ionicons locais; não compila o binário Android ou iOS.

Build web Cordova IFRNmacOS / Linux / Windows com Node
node src/MoodleIFRN/build-native.mjs --platform=android
node_modules/.bin/cordova prepare android
node_modules/.bin/cordova build android

O primeiro comando compila a aplicação web Cordova e gera o idioma pt-br. Os comandos seguintes preparam e compilam a plataforma.

No Windows PowerShell, execute os binários locais com .\node_modules\.bin\cordova.cmd. Para iOS, use --platform=ios e os comandos iOS descritos abaixo em um Mac.

Servir Ionic para desenvolvimentoScript existente

Executa ionic serve com HTTPS e valor de MOODLE_APP_BROWSER. O hook do Ionic também executa Gulp.

O script do repositório chama scripts/serve.sh em outro hook, então o fluxo de desenvolvimento completo pressupõe shell Unix (macOS/Linux ou Git Bash/WSL no Windows). Se falhar no Windows, use Git Bash/WSL; não altere scripts sem revisar os hooks.

09 · ARQUITETURA

Como as partes se relacionam

Marketplace IFRN→SUAP→Painel AVA→Curso Moodle nativo→Voltar ao Painel
  • src/MoodleIFRN/: customizações IFRN, Marketplace Angular, serviços, painel mobilemoodle, estilos, recursos, testes e scripts.
  • mobilemoodle/: painel web local com TypeScript/esbuild e SCSS; a sessão e as APIs do Painel não substituem a sessão Moodle nativa.
  • src/core/: núcleo Moodle Mobile; algumas integrações são reaplicadas por scripts de patch. Revisar diffs após atualizar o upstream.
  • Cordova: empacota WebView e plugins nativos; cordova.js é injetado/preparado no build, não é um asset web estático para remover.
  • SUAP/Gov.br: autenticação ocorre nos serviços oficiais. O retorno Gov.br ao Painel depende de handoff autorizado no servidor; o navegador externo não equivale a sessão autenticada no app.
  • P0.4: há histórico de teste crítico de concorrência entre sessões; consultar estado atual dos testes e patches antes de release pública.

O código experimental de AVA Aberto e outras branches não deve ser incorporado automaticamente. Confirme branch e diff antes de integrar.

10 · SUPORTE

Problemas comuns

Windows bloqueia npm.ps1

Use npm.cmd no PowerShell ou abra Git Bash. Não é necessário alterar a política de execução do sistema para esta tarefa.

NVM no Windows não entende lts/jod

Instale e selecione a versão numérica compatível com engines.node, por exemplo nvm install 22.17.0 e nvm use 22.17.0.

Gradle não baixa dependências

Confirme conexão a Google Maven/Maven Central, DNS, proxy, modo offline do Gradle e configuração de repositórios. Não desative TLS nem adicione repositórios desconhecidos.

cordova.js ausente

Confirme que foi executado o builder Cordova e cordova prepare. Um build web Angular isolado não garante a preparação do arquivo Cordova.

ADB não encontra aparelho

Execute adb devices -l, aceite a autorização USB no aparelho e confira cabo/modo de depuração. Não limpe dados como medida de diagnóstico.

Erro de espaço em disco (ENOSPC)

Verifique o espaço disponível e o caminho do cache antes de nova build. Preserve caches de Gradle/npm e arquivos do usuário; não use scripts de limpeza indiscriminados.

Patch IFRN diverge depois de atualizar Moodle

Revise o script e git diff em todos os destinos. Não execute patch repetidamente sem avaliar arquivos alterados; veja PATCH-AO-ATUALIZAR.md.

Fase 2: espera de navegação dos cursos

Estado: correção validada em testes locais; abertura de uma disciplina e retorno ao Painel confirmados manualmente no celular após instalar a atualização autorizada. Primeira conexão, troca de conta e cancelamento durante navegação continuam pendentes. Branch fix/ifrn-course-opening-phase2, baseada em 9f5603f4c. Commit da implementação: 74d0a4038 — fix(ifrn): encerra espera de rota após falha ou cancelamento.

Problema, causa e correção

Quando openNativeCourse() rejeitava a navegação, Promise.allSettled() ainda aguardava a confirmação da rota. Sem essa rota, o erro ficava retido até o timeout de 45 segundos. O observador também não reagia ao cancelamento explícito: depois de a operação nativa terminar, um Voltar podia continuar esperando um evento que não chegaria.

A abertura agora observa erros de rota imediatamente, aguarda a operação nativa terminar e propaga sua falha sem esperar uma confirmação impossível. O observador acompanha o AbortSignal da tentativa e libera timer e subscription ao concluir. A limpeza é idempotente. Uma navegação nativa ainda pendente continua mantendo o bloqueio de concorrência; cancelamento, falha e timeout continuam distintos.

Arquivos: services_mobile/moodle-site.service.ts e tests/course-navigation-failure.test.cjs. O log identifica openNativeCourse, que é a função realmente executada. Não houve alteração de OAuth, armazenamento, validação de identidade, loaders, núcleo Moodle ou plugins nativos.

Bloqueio da Ajuda após autenticar no SUAP

Depois da verificação inicial, o usuário abriu AVA (Moodle), informou as credenciais manualmente e relatou retorno à Ajuda com os links sem resposta. A inspeção encontrou o Painel visível e os seis links recebendo o hit testing, mas internalPageInBrowser e a tentativa do navegador continuavam ativos. A WebView SUAP estava oculta e a reserva contra atualização de perfil tinha contador zero. Não foi alteração de pointer-events, inert ou z-index.

Falha reproduzida: Ajuda e revalidação automática do perfil usavam o mesmo plugin sem compartilhar a reserva que já protegia o SSO dos cursos. O código Android do plugin substitui a janela e seu callback; a tentativa anterior pode não receber exit, deixando o Angular recusar novas aberturas. Três testes novos falharam antes da correção ao reproduzir essa concorrência, a consulta já pendente e o fechamento durante a espera.

Correção: commit 338163584, fix(ifrn): protege navegador da Ajuda contra atualização do perfil. SuapProfileBrowserService aguarda a consulta anterior e mantém a reserva compartilhada até sair, falhar ou cancelar; PainelAvaService expõe essa reserva sem alterar o contrato dos cursos. O fechamento durante a espera não cria uma janela tardia. Arquivos: services_mobile/painel-ava.service.ts, services_mobile/suap-profile-browser.service.ts, tests/suap-profile-browser.test.cjs e tests/help-profile-browser-race.test.cjs. Sem alteração de OAuth, cookies, URLs permitidas, núcleo Moodle ou plugin nativo.

Validação local: cinco regressões novas e os testes anteriores preservados; 365 testes aprovados em 51 arquivos locais. TypeScript aprovado. O serviço de navegação interna mantém lint sem apontamentos; o serviço do Painel mantém os 49 erros e 26 avisos anteriores, sem acréscimos.
