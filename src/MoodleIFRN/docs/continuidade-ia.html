GUIA DE CONTINUIDADE — AGENTES DE IA E DESENVOLVEDORES

Continue do ponto documentado

Use esta página junto das instruções curtas AGENTS.md. A página não substitui Git, código nem testes atuais: é um roteiro para consultar evidências existentes e preservar o trabalho em andamento.

01 · ORDEM DE LEITURA

O que ler primeiro

  1. AGENTS.md da raiz e AGENTS.md de MoodleIFRN.
  2. Portal HTML offline para ambiente, scripts, build e referências existentes.
  3. Arquitetura e arquivos críticos.
  4. Progresso do projeto e problemas conhecidos.
  5. Testes/fixtures e validação no aparelho físico.
  6. Para scripts específicos, consulte PATCH-AO-ATUALIZAR.md, PAINEL-CURSOS.md, SEGURANCA.md e os testes que cobrem os arquivos envolvidos.

O caminho para a raiz no link HTML serve a navegação relativa quando esta página abre via file://; se o navegador bloquear acesso fora da pasta, abra o arquivo AGENTS.md no editor.

02 · COMEÇAR UMA SESSÃO

Reconhecer o estado sem sobrescrever trabalho

git status --short --branch
git branch -vv
git worktree list
git log -10 --oneline
git diff --stat
  1. Registre branch, HEAD e worktrees; confira arquivos modificados, staged e não rastreados antes de editar.
  2. Leia o painel de progresso e a transferência da sessão anterior. Compare o objetivo pendente com o pedido atual do usuário.
  3. Confira se a correção já existe no código atual, em testes ou em commits desta branch. Histórico de outra branch não significa integração.
  4. Execute primeiro a linha de base relevante; anote falhas preexistentes e efeitos colaterais de scripts de build/patch.
  5. Edite apenas o menor escopo autorizado, preserve estado local e repita os testes pertinentes.

03 · NÃO FAZER

Limites que evitam regressões

  • Não iniciar refatoração geral nem repetir auditorias já documentadas sem uma pergunta concreta.
  • Não mudar autenticação SUAP, OAuth, identidade, sessão Moodle ou backend sem autorização e leitura do fluxo completo.
  • Não editar src/core/, src/addons/, plugins nativos ou configurações globais sem autorização explícita. Antes, explique arquivo, causa, por que não resolve em MoodleIFRN, riscos, testes e reversão.
  • Não apagar nem enfraquecer testes, P0.4, mocks, fixtures, harnesses, patches ou referências antigas só por parecerem sem uso.
  • Não executar git reset --hard, git clean, force push ou exclusão ampla; não misturar branches nem fazer merge/push sem autorização.
  • Não executar npm run patch:ifrn ou hooks sem ler seus efeitos. Scripts podem alterar core/configuração ou árvore Cordova gerada.
  • Não instalar/sobrescrever APK, desinstalar, limpar dados/cache, logout, trocar conta ou alterar configurações/permissões do telefone sem autorização explícita. Preservar a sessão real.
  • Não afirmar que login, curso, performance ou acessibilidade estão resolvidos com base só em teste unitário ou build.
