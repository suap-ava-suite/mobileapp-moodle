ÚLTIMA CORREÇÃO · 14/11/2026

Barra de status e integração do Painel na release

Estado: correção implementada e instalada; usuário confirmou o resultado e autorizou commit/push com documentação para release/2.0.1. Origem perf/ifrn-course-shell, correção c217d4481; base remota de integração ad6dded4b. A integração é preparada em integrate/ifrn-panel-release, worktree limpo; os outros worktrees com alterações locais foram preservados. Confira o HEAD e o remoto no Git antes de continuar.

Causa, correção e evidência

O cabeçalho do Painel Angular ficava sob a barra de notificações/status. Na WebView do Moto G20/Android 11, o Android fornecia --ion-safe-area-top = 28,5714 px (50 pixels físicos com DPR 1,75). O CSS de página independente redefinia essa variável no host para env(safe-area-inset-top, 0px), que era zero. Os botões começavam em y=10 px e a toolbar não reservava espaço para o sistema.

scripts/painel-angular-theme.cjs agora transforma somente os quatro resets de --ion-safe-area-* no host em inherit. O Ionic continua responsável pelo recuo: não foi criada margem fixa, não foi ocultada a barra do Android e não foi alterado o núcleo. A folha painel/painel-native-theme.css foi regenerada; o CSS do Painel web independente foi preservado. A regressão acrescentada falhou antes da correção e passou depois.

Na APK instalada, sem override inline de diagnóstico, a toolbar apresentou padding superior de 28,5714 px e altura de 92,5714 px; os botões começaram em y=38,5714 px e a logo em y=44,5714 px, abaixo da área do sistema. A conta e os dados foram preservados com adb install -r, após conferência de package/certificado. O teste adicional automatizado da animação da Ajuda expirou; não houve nova validação física completa desse painel nesta rodada.

Build web MoodleIFRN e Cordova Android aprovados; bridge Cordova completo (63.747 bytes) e módulo Moodle com wrapper verificados. A APK anterior aprovada foi guardada fora do Git. Grupo de tema/componente: 8/8. Na integração limpa: 388 testes Node, 383 aprovados e cinco contratos P0.4 reprovados, zero ignorados/cancelados (8,8 s). TypeScript e ESLint dos três arquivos TypeScript novos passaram. Os cinco contratos persistentes da implementação experimental retirada continuam intactos; não declarar P0.4 resolvida. Jest, cobertura e nova APK compilada na branch de integração não foram executados; a APK física corresponde ao candidato de origem.

Compatibilidade da integração

A release continha a reversão 815f02dc2, que havia removido vlibras-widget.ts e estilos presentes no candidato testado. As dependências e estilos correspondentes foram incorporados para manter o Painel compilável e coerente com a APK, preservando os imports limpos e as cinco exclusões auditadas da release. O inventário atual mantém 37 fixtures. O teste de VLibras voltou a consultar o HTML e o Markdown nos caminhos migrados; a comparação de CSS normaliza somente CRLF/LF para funcionar em checkout Windows.

Próxima ação: manter o Painel Angular e o tema aprovados; tratar apenas os próximos erros relatados pelo usuário. Não reaplicar o patch experimental, não restaurar resets de insets do painel independente e não presumir que um worktree antigo de release represente o remoto atualizado. Painel Angular com tema institucional recuperado

Avaliação do usuário no Moto G20: o Painel ficou “quase perfeito” e está bom como referência. O usuário apontará os ajustes restantes depois. Não tratar essa avaliação como aprovação de todos os fluxos ou como autorização para outra reformulação.

Implementação na branch isolada perf/ifrn-course-shell, base a0e5d553c, HEAD funcional ee06ed1a3. O diretório original continua na branch test/ifrn-unit-regression: seus 236 caminhos preexistentes foram preservados. Use git worktree list para localizar a implementação; não presuma que a release ou o checkout original contenham essas mudanças. Uma cópia documental de continuidade pode estar disponível nesse checkout sem integrar o código.

O que mudou e por quê

  • painel/painel-native.ts, HTML e SCSS: Painel em componentes Angular, OnPush, signals e eventos para os serviços existentes. A tela ativa não instancia iframe. Diários, Coordenação, Autoinscrição, favoritos, perfil, Ajuda, filtros e opções de acessibilidade têm handlers Angular; cobertura física ainda é parcial.
  • O primeiro layout Angular alterou a aparência e foi rejeitado. A restauração mantém o tema original: cores, fonte Rawline, abas, filtros, cartões, indicadores de publicação, favoritos e painéis laterais. A causa comprovada do tema incompleto era o uso de seletores :root e body dentro dos estilos encapsulados do Angular: as variáveis não chegavam ao componente.
  • scripts/painel-angular-theme.cjs adapta os seletores do CSS original para :host/:host-context e relocaliza fontes. mobilemoodle/build.mjs gera painel/painel-native-theme.css a partir do mesmo SCSS. Não editar a folha gerada manualmente. Testes confirmam a preservação das declarações, animações e assets; não foi desativado o encapsulamento nem adicionado tema global ao Moodle.
  • A primeira sessão Moodle de outra conta falhava antes de abrir o navegador: a versão experimental P0.4 lia CORE_SITE_CURRENT_SITE_ID_CONFIG sem valor padrão em CoreSites.beginSessionAttempt. Não havia registro nesse cenário. A pedido explícito do usuário, a aplicação automática desse experimento foi desativada. O candidato usa o núcleo e plugin oficiais, callback oficial, validação de site/identidade e fila local de callbacks não canceláveis. Os testes e patches históricos permanecem. Isso não comprova a resolução da concorrência persistente P0.4.
  • Foi corrigida uma falha de empacotamento introduzida nesta sessão: copiar o JS bruto do plugin para a plataforma removeu o wrapper cordova.define e prendeu o app na logo. O wrapper foi restaurado; o guard agora rejeita módulo sem wrapper, cordova.js vazio e baseline de sessão divergente. Não repetir cópia parcial de plugins ou assets.
