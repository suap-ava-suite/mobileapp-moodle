Referência com trechos legados: este documento mistura contratos atuais e referências de protótipo. Confirme cada rota no código e no serviço implantado antes de integrá-la; não use exemplos com tokens reais.

O app usa três bases:

  1. Autenticação SUAP — https://suap.ifrn.edu.br (/api/token/pair)
  2. Painel AVA (preferido) — https://painel.ead.ifrn.edu.br (/api/v1/authenticate/, /api/v1/diarios/)
  3. Fallback diários — API SUAP ensino (/api/ensino/…) se o Painel estiver indisponível

Detalhes da ponte: PONTE-PAINEL-MOODLE.md.

Este documento descreve o que o cliente espera.

Autenticação (SUAP)

DOCUMENTAÇÃO TÉCNICA

POST /api/token/pair

Body

Exemplo de códigojson
{
  "username": "matricula-ou-cpf",
  "password": "senha"
}

Resposta 200 (SimpleJWT)

Exemplo de códigojson
{
  "username": "matricula-ou-cpf",
  "refresh": "[REFRESH_TOKEN_EXAMPLE]",
  "access": "[ACCESS_TOKEN_EXAMPLE]"
}

O AuthService converte para o formato interno access_token / refresh_token / token_type.

Erros esperados pelo cliente

StatusTratamento na UI
400 / 401IFRN-id ou senha inválidos
429Muitas tentativas
5xxSUAP indisponível
timeout / offlineMensagens específicas

DOCUMENTAÇÃO TÉCNICA

POST /api/token/refresh

Body

Exemplo de códigojson
{
  "refresh": "[REFRESH_TOKEN_EXAMPLE]"
}

Resposta 200

Exemplo de códigojson
{
  "refresh": "[REFRESH_TOKEN_EXAMPLE]",
  "access": "[ACCESS_TOKEN_EXAMPLE]"
}

Usado após biometria. Se retornar 401, o app desativa a biometria local e pede login com senha.

DOCUMENTAÇÃO TÉCNICA

POST /api/token/verify

Body

Exemplo de códigojson
{
  "token": "[ACCESS_TOKEN_EXAMPLE]"
}

Confere se o access token ainda é aceito pelo SUAP.

Painel (Bearer obrigatório)

Header em todas as rotas abaixo:

Exemplo de códigohttp
Authorization: Bearer <access_token>
Accept: application/json

O painel não usa mais /dashboard/ da FastAPI. Após o login SUAP, os dados vêm destes endpoints (adaptados em api-suap.ts):

Uso internoEndpoint SUAP
Nome / foto / papelGET /api/rh/eu/
Lista de diáriosGET /api/ensino/meus-periodos-letivos/ + GET /api/ensino/diarios/{ano}.{periodo}/ (fallback: GET /api/ensino/meus-diarios/)
Detalhe do diárioGET /api/ensino/minha-turma-virtual/{id}/ (fallback: aulas/materiais/tópicos do diário)

Formato interno esperado pela UI (DashboardData):

Exemplo de códigojson
{
  "nome": "Nome do estudante",
  "username": "matricula",
  "papel": "estudante",
  "total_courses": 3,
  "courses": [
    {
      "id": 1,
      "name": "Nome da disciplina",
      "shortname": "SIGLA",
      "progress": 40,
      "moodle": "SUAP"
    }
  ],
  "diarios": [],
  "autoinscricoes": []
}

A aba Diários usa diarios se existir; senão cai em courses. A aba Autoinscrição usa autoinscricoes (hoje vazia no adaptador SUAP).

GET /courses/{id} (legado)

id numérico.

Exemplo de códigojson
{
  "id": 1,
  "name": "Nome do curso",
  "teacher": "Professor(a)",
  "workload": "60h",
  "progress": 40,
  "moodle": "AVA Acadêmico",
  "summary": "Texto opcional de visão geral",
  "sections": [
    {
      "name": "Tópico 1",
      "activities": [
        {
          "name": "Fórum de avisos",
          "modname": "forum",
          "completion": true
        },
        {
          "name": "Material da aula",
          "modname": "resource",
          "completion": false
        }
      ]
    }
  ]
}

Campos de atividade aceitos: modname (ou module / type), name (ou title), completion (boolean opcional). Seções aceitam activities, modules ou cms. ---

Status HTTP que o painel trata

StatusComportamento
401 / 403Limpa token e pede novo login
404Tela “não encontrada”
408Timeout (cliente)
429Muitas tentativas
500 / 502 / 503 / 504Telas de erro com retry quando aplicável
0Falha de rede / servidor offline

Resposta de sucesso deve ser Content-Type: application/json.

Tokens

  • Preferência: JWT com claim exp
  • O cliente valida formato e expiração de forma local (não valida assinatura)
  • Em produção, o backend deve validar assinatura e permissões

DOCUMENTAÇÃO TÉCNICA

Observação

A autenticação já aponta para o SUAP oficial. O painel ainda pode usar FastAPI de teste para cursos/diários. Quando a API de produção do AVA chegar:

  1. Manter os paths do painel (ou adaptar só os serviços)
  2. Trocar a base URL do painel
  3. Garantir CORS + HTTPS + JWT aceito pelo backend AVA
Nenhum tópico corresponde à pesquisa.
